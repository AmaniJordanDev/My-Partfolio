How I Built Uganda2Congo

A complete breakdown of building a professional cross-border marketplace platform connecting businesses across Uganda and Congo — from concept to a production-ready platform.

Amani Jordan
september 20, 2026
18 min read
HTML/CSS/JavaScript Marketplace Platform Full Stack

The Vision

Uganda2Congo started as a simple question: "What if we could make it easy for businesses in Uganda to reach customers in Congo, and vice versa?" I noticed a massive gap in cross-border e-commerce in East Africa. While global platforms dominate, there was no dedicated marketplace designed specifically for African entrepreneurs to connect with each other.

I decided to rebuild an existing Uganda2Congo project from scratch with a modern, professional approach. The goal was to create a platform that feels premium, works seamlessly on mobile and desktop, and makes it incredibly easy for businesses to showcase their products and services.

What started as a rebuild turned into a complete transformation of the platform's user experience, design system, and functionality. This article breaks down exactly how I built it.

The Challenge: Starting With Broken Foundations

When I took on this project, the existing Uganda2Congo platform had several issues:

  • Broken Navigation: Links pointing to wrong pages, homepage logo broken, menu inconsistencies
  • Poor Visual Design: No cohesive design system, inconsistent styling across pages
  • Not Responsive: Desktop-only experience, unusable on mobile devices
  • No Functionality: Search and filtering didn't work properly
  • Limited Features: No business directory, no proper categorization
  • Language Support Missing: Only English, but needed to serve multilingual audience

The biggest challenge wasn't building something from scratch — it was rebuilding something that partially worked while maintaining the original vision. I had to decide what to keep, what to fix, and what to completely reimagine.

Building a Professional Design System

The first thing I did was create a cohesive design system. I couldn't just use random colors and hope they worked together. Instead, I drew inspiration from Uganda and Congo's flags while creating a modern, professional palette.

Color Strategy

Rather than using flag colors directly (which would be garish), I used them strategically:

  • Yellow (#FCDC04): Primary CTAs and important actions — from Uganda's flag
  • Congo Blue (#007FFF): Secondary elements and links — representing Congo
  • Navy (#031A2B, #062C49): Professional dark backgrounds — creates premium feel
  • White (#FFFFFF): Clean surfaces and text — maximizes readability
  • Red: Minimal accent use only — not dominant

Typography System

I chose two complementary font families that are widely available and work great on all devices:

  • Montserrat: Bold, geometric headings — commands attention
  • Poppins: Friendly, readable body text — excellent at all sizes

Component Library

I created reusable components with consistent CSS classes:

  • Buttons: Primary, secondary, large, small variations
  • Cards: Business cards, product cards, service cards
  • Forms: Inputs, selects, textareas with consistent styling
  • Navigation: Navbar, mobile menu, breadcrumbs
  • Sections: Hero, features, grid layouts

Architecture & File Organization

I kept it simple. No build tools, no bundlers, no unnecessary complexity. Just clean HTML, CSS, and JavaScript.

Why Vanilla JavaScript?

I chose vanilla JavaScript over React/Vue for several reasons:

  • Performance: No framework overhead, lightning-fast
  • Easy to Learn: Future developers can jump in immediately
  • Simplicity: No build process, works in any environment
  • Scalability: Can add a backend without major refactoring
  • Browser Support: Works everywhere, even older devices in rural areas

Core Features I Built

1. Responsive Navigation System

The navbar needed to work perfectly on every screen size. I built a mobile hamburger menu that:

  • Appears only on screens under 768px
  • Smoothly animates when opened/closed (hamburger becomes X)
  • Auto-closes when a link is clicked
  • Closes when clicking outside
  • Can be closed with the Escape key

2. Business Directory with Smart Filtering

The businesses page is the heart of Uganda2Congo. I built a sophisticated filtering system that searches by:

  • Search: Real-time search by business name, category, or description
  • Country: Filter by Uganda, Congo, or both
  • Category: 8 business categories with visual browsing
  • No Results Handling: Professional message when nothing matches

3. Marketplace with Advanced Filtering

The marketplace page goes deeper with product-level filtering:

  • Product Search: Find products by name or description
  • Price Range: Min/max price filtering
  • Location Filter: Products from specific locations
  • Rating Filter: Filter by seller ratings
  • Smart Sort: Newest, price low-to-high, price high-to-low, top rated

4. Authentication System

I built a complete auth flow for sellers:

  • Login Page: Email and password validation
  • Multi-Step Signup: 3-step signup wizard (account info, business info, verification)
  • Password Toggle: Show/hide password with eye icon
  • Validation: Real-time form validation with error messages
  • Session Management: localStorage for user sessions

5. Seller Dashboard

Once logged in, sellers get a dashboard to manage their businesses:

  • Dashboard Analytics: See key metrics at a glance
  • Business Management: Add, edit, delete businesses
  • Product Management: Manage product listings
  • Inquiries: Track customer inquiries and messages
  • Analytics: View performance metrics

6. Multi-Language Support

Uganda2Congo needed to serve multiple language communities:

  • English: Complete translations
  • Luganda: Ugandan language
  • Kiswahili: East African lingua franca
  • Français: French for Congolese users
  • Lingála: Congolese language

The language system works by storing a translations object in JavaScript and dynamically updating the DOM when the user changes languages. The preference is saved in localStorage so it persists across sessions.

Building a Truly Responsive Design

I tested on actual devices and breakpoints, not just browser devtools. The platform needed to work on:

Mobile (320px - 480px)

On small phones, I focused on simplicity:

  • Single column layouts
  • Larger touch targets (minimum 44px)
  • Minimal images to reduce data usage
  • Simplified forms (fewer steps where possible)
  • Bottom-aligned CTAs for thumb reach

Tablet (481px - 1024px)

Tablets get a richer experience:

  • Two-column layouts where appropriate
  • Larger images for better visual impact
  • Grid-based product displays
  • Sidebar content becomes visible

Desktop (1025px+)

Full desktop experience:

  • Multi-column layouts
  • Sidebar navigation
  • Full-featured filters
  • High-resolution images
  • Advanced hover effects

Responsive Typography

I used CSS clamp() for fluid typography that scales smoothly:

/* Hero title scales from 1.75rem to 3.5rem */
font-size: clamp(1.75rem, 5vw, 3.5rem);

This eliminates the need for multiple media queries for text sizing while ensuring perfect readability at every breakpoint.

Challenges I Faced & How I Solved Them

Challenge 1: Fixing Broken Navigation Without Breaking Code

Problem: The homepage logo pointed to `#`, the businesses link was broken, and there were inconsistencies across pages.

Solution: I created a single navbar component and included it consistently across all pages. I used semantic HTML and proper link attributes. Most importantly, I standardized the navigation structure so changes in one place automatically sync everywhere.

Challenge 2: Search & Filtering Without a Backend

Problem: Couldn't hit a database to search, but needed real-time filtering to feel responsive.

Solution: I implemented client-side filtering using JavaScript's `filter()` and `includes()` methods. The data lives in the HTML as `data-*` attributes, and JavaScript searches/filters on demand. It's fast because the dataset is small, and it works offline.

Challenge 3: Category Cards with Professional Images

Problem: The original design used single letters (R, S, T) for categories, which looked unprofessional.

Solution: I replaced them with real, high-quality category images:

  • 🍽️ Restaurants → Professional restaurant/dining imagery
  • 🏬 Retail → Busy marketplace/store photos
  • 🚛 Transport → Logistics/delivery vehicles
  • 🏗️ Construction → Building materials and sites
  • 👗 Fashion → African clothing and textiles
  • 💻 Technology → Modern office/workspace imagery
  • 🌾 Agriculture → Farming and crop production
  • 🏢 All Businesses → Professional marketplace overview

For the demo, I used Unsplash image URLs (which are free and high-quality). For production, these would be uploaded to a proper CDN and served from your own infrastructure.

Challenge 4: Building Multi-Language Support

Problem: The platform needed to support 5 languages but I didn't have a translation management system.

Solution: I created a translations object in JavaScript:

const translations = {
en: { home: 'Home', about: 'About', ... },
lg: { home: 'Nyumba', about: 'Okukubaganya', ... },
sw: { home: 'Nyumba', about: 'Kuhusu', ... },
fr: { home: 'Accueil', about: 'À propos', ... },
ln: { home: 'Monkonzi', about: 'Makanisi', ... }
}

When the user changes language, JavaScript finds all elements with `data-i18n` attributes and updates their text content. The language preference is saved in localStorage so it persists.

Challenge 5: Mobile Menu That Actually Works

Problem: Mobile menu was flaky — sometimes it wouldn't close, sometimes links didn't work.

Solution: I built a robust menu system with multiple close triggers:

  • Click hamburger button → toggles open/closed
  • Click a navigation link → closes menu
  • Click outside the menu → closes it
  • Press Escape key → closes it

This redundancy ensures users can always close the menu, even if one method doesn't work. The animation is smooth with CSS transitions, and the menu slide-in is hardware-accelerated for performance.

Tech Stack & Why These Choices

Frontend

  • HTML5: Semantic markup, accessibility built-in
  • CSS3: Flexbox, Grid, CSS variables, animations
  • Vanilla JavaScript: No framework, pure DOM manipulation

Fonts & Icons

  • Google Fonts: Montserrat (headings), Poppins (body)
  • Font Awesome: 1,000+ icons for UI elements

Deployment (Current Demo)

  • Static Hosting: Can be deployed to Vercel, Netlify, GitHub Pages
  • No Backend Required: For demo/prototype phase

Future Production Stack

When moving to production, I'd recommend:

  • Frontend: React or Vue (for scalability)
  • Backend: Node.js + Express or Python + Django
  • Database: PostgreSQL or MongoDB
  • Authentication: Firebase or Auth0
  • Payments: Stripe or Flutterwave
  • Hosting: AWS, GCP, or Railway

The filtering system searches across multiple fields simultaneously:

cards.forEach(card => {
const matches =

Language Switching

Simple but powerful approach to multi-language support:

function changeLanguage(lang) {
document.querySelectorAll('[data-i18n]')
.forEach(el => {
const key = el.dataset.i18n;
el.textContent = translations[lang][key];
});

localStorage.setItem('language', lang);
}

Mobile Menu Toggle

Robust menu system with multiple close triggers:

hamburger.addEventListener('click', () => {
menu.classList.toggle('active');
});

// Close on link click
menuLinks.forEach(link => {

// Close on Escape
document.addEventListener('keydown', (e) => {
if (e.key === 'Escape') {
menu.classList.remove('active');
}
});

What I Learned Building Uganda2Congo

1. Design Systems Save Time

Spending 2 days upfront to build a proper design system with CSS variables, reusable components, and a consistent color palette saved me weeks of debugging and refactoring later. The ROI on good design systems is massive.

2. Mobile-First Isn't Optional in Africa

Over 80% of internet access in Uganda and Congo is via mobile. Designing for desktop first would have excluded the majority of users. Mobile-first design isn't a nice-to-have — it's essential.

3. Vanilla JavaScript Can Scale

I initially thought we'd need React for this complexity. But vanilla JavaScript with well-organized code and proper separation of concerns scales beautifully. The platform handles hundreds of items without performance issues.

4. Localization Matters

Adding Luganda, Kiswahili, and Lingála support wasn't just nice-to-have — it dramatically improved usability. English-only platforms alienate the majority of the population who speak local languages.

5. File Organization Prevents Debugging Hell

Keeping separate stylesheets for different pages (`style.css` for global, `businesses.css` for that page) prevented CSS conflicts and made debugging trivial. A messy codebase costs more than it saves.

6. Demo Data Matters

Real, relevant demo data (actual Ugandan and Congolese business names like "Kampala Restaurant" and "Congo Fabrics") makes the platform feel real. Generic placeholders ('Business 1', 'Business 2') don't sell the vision.

The Real Lesson

Building Uganda2Congo taught me that great products aren't built through complexity — they're built through clarity. A well-organized vanilla JavaScript codebase beats a hastily-thrown-together React app. A cohesive design system beats random styling decisions. Mobile-first design beats desktop-first assumptions.

The platform started as a rebuild of something broken. But the rebuild process — questioning every choice, fixing every bug, optimizing every interaction — transformed it into something genuinely great.

If you're building a marketplace, a platform, or any web application, the principles here apply: start with design, organize your code, test on real devices, respect your users' devices and bandwidth, and build for the people who actually use your platform (not just the ideal case).

Uganda2Congo isn't perfect, and it's not finished. But it's a solid foundation built the right way — semantic HTML, clean CSS, purposeful JavaScript, and a relentless focus on the user experience.
